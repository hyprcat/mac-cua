## Codebase Patterns
- Build/test from the `swift/` dir: `cd swift && swift build && swift test`. Toolchain: Swift 6.x.
- `MacCUACore` + `MacCUAServer` are **Linux-pure**: NO macOS framework imports (no AppKit/CoreGraphics/ApplicationServices/ScreenCaptureKit/Vision/IOKit). All macOS code goes in `MacCUAKit`/`CSkyLightShim`/the executable behind `#if os(macOS)`.
- Port behavior from the Python reference in `app/` + `app/_lib/`; match the existing test intent.
- Provider protocol seams are already defined in `swift/Sources/MacCUACore/Providers.swift` — Phases 3–6 implement them in `MacCUAKit`.
- **Prime Invariant:** never foreground / activate / warp-cursor / global-post. Banned symbols are guarded by story US-012; never weaken those guards.
- Target the **experimental confirmed-delivery pipeline** (transport-confirm via delivery tap + snapshot-as-truth + `compute_verdict`). Do NOT re-enable inline post-delivery AX verification on primary paths (Invariant 21).
- Exact SPI symbols + CGEvent field numbers: `docs/CODEX_PARITY_CHANGES.md` Appendix. The 23 invariants: `docs/SWIFT_PORT_DESIGN.md` §3.
- **Speed:** decompose each story and run Sonnet/Opus sub-agents in parallel (read Python / draft Swift / write tests / audit invariants).

## US-004 — Request/turn-scoped cache (L1) in Core
- Implemented `swift/Sources/MacCUACore/TurnCache.swift`: a reference-type `TurnCache` with one-turn/batch lifetime porting apps.py's `_pid_cache`/`_ax_app_cache`/`invalidate_caches_for_pid`. Three maps — name→pid, pid→AppState, pid→pre-action `[Node]` tree (batch reuse). All reuse passes through an injected `isPidAlive` predicate so the "validate the PID is alive before reusing" rule survives with zero macOS deps (Core stays Linux-pure). Stores only pure Sendable values — the AX app handle stays in Kit. `invalidate(pid:)` drops AppState+tree+all names for that pid; `invalidateTree(pid:)` drops only the tree (post-action re-walk without re-resolving); `clear()` tears down the turn. Explicitly distinct from the Phase-3 SCContentFilter capture cache (keyed by window/display).
- Tests: `swift/Tests/MacCUACoreTests/TurnCacheTests.swift` (9 cases: pid hit/miss, dead-pid eviction on name+appstate lookup, appstate hit/miss, batch-reuses-pre-action-tree = single walk over 3 steps, invalidate-pid drops all names+state+tree but spares other pids, invalidate-tree keeps pid+state, clear wipes all).
- Sub-agents used: none — small contained pure-logic story done directly in main thread (matches US-001..003 sizing).
- Quality gate: `swift build` clean; `swift test` 393 passed / 0 fail (was 385).
- Learnings: model L1 as a reference type (reuse within a turn IS the point) and inject liveness rather than importing a macOS pid check — keeps Core pure. Eviction-on-dead-pid happens lazily at read time (matches apps.py validate-before-reuse) rather than eagerly. Keep two invalidation granularities: full `invalidate(pid:)` for app-identity changes and `invalidateTree(pid:)` for the common post-action re-walk so the batch (US-008) doesn't re-resolve the app each step.

## US-005 — select_text range-resolution (D1 pure tier) in Core
- Implemented `swift/Sources/MacCUACore/SelectTextRange.swift`: `TextRange{location,length}`, `CaretPlacement{select,before,after}`, `SelectTextResolution{resolved,notFound,ambiguous(count)}`, and `SelectTextResolver.resolve(text:target:prefix:suffix:caret:)`. Pure resolver scans for all occurrences of `target` in UTF-16 code units (CFRange-compatible so the Mac tier US-040 can feed the result straight to AXValueCreate(.cfRange,...)). prefix = text immediately before the match must end-with; suffix = text immediately after must begin-with. Exactly one survivor => `.resolved`; zero => `.notFound`; >1 => `.ambiguous(count)`. Caret-before/after collapse to zero-length ranges at match start / match end; empty target => zero-length caret at 0.
- Tests: `swift/Tests/MacCUACoreTests/SelectTextRangeTests.swift` (14 cases: unique, at-start, not-found, target-longer-than-text, duplicate-ambiguous, prefix/suffix/both disambiguation, prefix-no-match=notFound, caret before/after, empty target, UTF-16 emoji offset, still-ambiguous-after-prefix).
- Sub-agents used: none — small contained pure-logic story done directly in main thread (matches US-001..004 sizing). Python `selection.py` has no content/prefix/suffix resolver (Codex-parity new feature); implemented from the acceptance spec.
- Quality gate: `swift build` clean; `swift test` 407 passed / 0 fail (was 393).
- Learnings: resolve selection offsets in UTF-16 code units, not Character offsets — AXSelectedTextRange is a CFRange so UTF-16 is what the Mac impl needs (a Character-based location would mis-place selections past any emoji/astral char). Disambiguation semantics: prefix = "preceding text ends with", suffix = "following text begins with" — adjacency to the match, not anywhere in the string.

## US-007 — Confirm InputStrategy pointer-first for Chromium/Electron (C1)

- Quality gate: `swift build` clean; `swift test` 431 passed / 0 fail (was 420).

The doc's "AX-first for menu items" holds only for native Cocoa + browser-chrome. ## US-008 — batch tool (D3): N actions / one MCP call
- New `batch` tool def appended to `ToolDefs.swift` (10th tool; the original 9 unchanged): schema = `{actions: [array of {tool, + that tool's params, optional window_id/app retarget}]}`, required `["actions"]`. New `SessionManager+Batch.swift`: `executeBatch(_:)` routed from `execute()` (alongside the `list_apps` special-case). Semantics: linear, stop-on-first-failure (remaining steps reported `not run`), exactly ONE settle + ONE final snapshot at the end, per-step outcome list in `response.result` + a summary line. Each step may retarget via window_id/app, else inherits the previous step's session. Per-step safety/approval/lifecycle; restores the user's previous frontmost once (Inv 15). Reuses the turn cache (US-004): `ensureBatchPreActionTree` walks the tree at most once for the whole batch and reuses it for every element-index resolution (`cache.invalidateTree(pid:)` after each step so the FINAL snapshot re-walks, but intermediate steps do not). `execute()` never throws — empty/malformed `actions`, unsupported step tool (only the 7 action tools are batchable; not list_apps/get_app_state/batch), and first-step-without-target all become a failproof result/error response.
- Tests: `BatchTests.swift` (7 cases: success path runs all steps + final snapshot + ordered key delivery; halt-on-first-failure marks remainder not-run + only pre-failure effects ran + final snapshot still present; empty actions → error; missing actions → error; unsupported tool fails; first action without target fails; pre-action tree reuse asserts `walkCount == 2` over a 3-step batch). Added a `walkCount` recorder to `FakeAccessibility.walkTree`. Updated `ServerLayerTests` catalogue assertions (9 → 10, last == "batch").
- Sub-agents used: none — contained spine-logic story; understood the full execute/dispatch/snapshot spine and implemented directly in the main thread (matches US-001..007 sizing).
- Quality gate: `swift build` clean; `swift test` 438 passed / 0 fail (was 431).
- Learnings: batch is a NEW Codex-parity surface (no Python reference) — model it as a peer of `list_apps` inside `execute()`, NOT by looping `execute()` (which would snapshot+settle per step and defeat the whole round-trip win). The "reuse the pre-action tree" requirement (US-004) is realized by (a) not snapshotting between steps so `session.treeNodes`/`refetchableTree` persist, and (b) a per-batch `TurnCache` whose `invalidateTree(pid:)` is called after each step so only the FINAL snapshot re-walks — `walkCount` over fakes is the testable proof. `resolveIndex` prefers `refetchableTree` then falls back to `session.treeNodes`, so populating `treeNodes` alone is enough for element-index steps to resolve against the cached tree.

## US-009 — wait tool (D4)
- New `wait` tool def appended to `ToolDefs.swift` (11th tool): `{app?, window_id?, timeout?}`, no required fields. New `SessionManager+Wait.swift`: `executeWait(_:)` routed from `execute()` (alongside `list_apps`/`batch`). Semantics: read-only/state-only (NO frontmost save-restore, NO user-interaction tap — there is no effect to attribute, so the Prime Invariant holds trivially); resolves the target session, runs safety/approval/lifecycle-track (no step increment), then drives the same `DebounceStateMachine` via `session.settleMonitor.waitForSettle(context:"wait", timeout:…, quietPeriod: settleQuietPeriod)` with the requested timeout, then returns a fresh `takeSnapshot`. Timeout clamped to `[0, 10.0]`, default 2.0; a non-positive timeout (or no monitor) skips settle and reports "already quiet". `waitResultText` maps SettleResult → message (settled / noChange / cancelled / timeout-hit-cap). Added `doubleArg` JSON-variant coercion helper (mirrors `intArg`/`stringArg`).
- Tests: `WaitTests.swift` (6 cases: default-timeout settles + snapshot returned, requested-timeout pass-through, clamp-to-cap, hit-the-cap path via `FakeSettleMonitor.result=.timeout` still returns snapshot + honest message, zero-timeout skips settle, no-target → clean error). Made `FakeSettleMonitor.result` configurable (was hardcoded `.settled`). Updated `ServerLayerTests` catalogue assertions (10→11, last == "wait").
- Sub-agents used: none — contained spine-logic story reusing the US-008 batch pattern; implemented directly in the main thread (matches US-001..008 sizing).
- Quality gate: `swift build` clean; `swift test` 444 passed / 0 fail (was 438).
- Learnings: `wait` is a NEW Codex-parity surface (no Python ref). Model it as a peer of `list_apps`/`batch` inside `execute()`, NOT through `dispatch()` (which expects an action tool + would do the full effect pipeline). It is read-only so it must NOT save/restore frontmost or open the interaction tap. The SettleMonitor seam already abstracts the DebounceStateMachine poll loop, so "drive the machine with the tool timeout" is literally one `waitForSettle` call — the Kit impl (US-025) owns the real clock/poll. `FakeSettleMonitor` now exposes a settable `result` so settle-outcome branches are testable on Linux.
